# Terrarium 아키텍처

> CONCEPT.md를 구현 단위로 옮긴 문서다. 첫 빵은 `example/proto`(OHT 모니터링 화면)이며, 이 문서의 모든 결정은 그 화면을 실제로 구워낼 수 있는지를 기준으로 했다.
> 사용자에게 보이는 이름은 **테라리움(Terrarium)** 하나다. Bethlehem(작성 프로그램)·Manna(내보낸 문서)는 코드와 이 문서 안에서만 쓰는 코드명이다.

**D-13 근거.** 문서 하나를 원본으로 두면 큰 파일을 매번 풀었다 묶어야 하고, 원본 프로토타입 폴더와의 연결·돌아온 문서 모으기·Git 관리가 어렵다. 작업 폴더를 원본으로 두면 실행할 때 마지막 폴더와 화면이 그대로 열리고, 원본 폴더가 바뀌면 새 버전을 권하고, `returned/` 에 넣은 회신본을 알아채고, 화면별 JSON 이라 Git diff 가 읽힌다. 테라리움 문서 안의 데이터만으로 작업 폴더를 완전히 복원할 수 있다(문서 열기 → "작업 폴더로 풀기") — 자기완결성 원칙과 맞는다.

**D-14 근거.** URL 을 담는 방식(첫 시도: 별도 창에서 담기)은 사용자 지정 테스트 사이트(`semicon-xms.xdt.com/monitor`)의 지도를 비워 버렸다. 지도가 커스텀 요소의 shadow DOM 안 WebGL 캔버스이고(DOM 복제로 담기지 않는다), 데이터가 WebSocket·POST GraphQL 로 오기 때문이다(응답 재생으로 낼 수 없다). 편집기에서는 사이트를 그대로 띄우는 것이 정답이고, 보낼 사본은 그런 부분을 픽셀로 담는다(§5.5).

**D-2 근거.** Manna 런타임은 품은 화면과 한 파일에 같이 실린다. Preact는 React 문법을 그대로 쓰면서 작고, 같은 컴포넌트를 Bethlehem 렌더러에서도 쓴다.

**D-5 근거.** 빵이 곧 반죽이다. 기획자는 테라리움 문서를 열고 저장한다. 수신자에게 보내는 것도, 돌려받는 것도 같은 형식이다. "원본 따로, 보낸 것 따로"가 없으므로 최신본이 어느 것인지 헷갈리지 않는다.

**D-8 근거.** 유형·상태 같은 정형 필드는 기획자마다 쓰는 법이 달라 결국 본문에 다시 적게 된다. 옵시디언처럼 마크다운 하나로 두고, 확인이 필요한 일은 체크박스로 적는다. 수신자는 남의 Comment 본문은 고칠 수 없지만 체크박스는 누를 수 있다.

## 2. 첫 빵 분석 — `example/proto`

| 관찰 | 실제 | 대응 |
|---|---|---|
| 구성 | `index.html` 470KB + `data/*.js` 2.9MB + `assets/` 2.7MB | `assets/` 이미지 3개는 `index.html`이 참조하지 않는다 → 등록 때 "참조 없음 · 제외"로 제안 |
| 데이터 로딩 | `createElement('script')` 후 `s.src = 'data/${key}.js'` 동적 삽입 | 가상 파일 시스템 shim (§5) |
| 화면 본체 | `<canvas>` 16개 (3D 맵, FAB 조망, 레이더, 미니맵) | **요소 + 요소 내 상대 영역** 앵커 (§6) |
| 화면 상태 | FAB 조망 → BAY-4 상세, 설비정보 탭, LIVE/REC, 보조 창 | 앵커가 보일 때만 마커 표시, 클릭 경로를 남겨 그 상태로 돌아간다 (§6.4) |
| 움직임 | rAF 루프, 13.4초 순환 | 마커는 매 프레임 위치 추적. 일시정지(§5.4), 녹화(§7) |
| 해상도 | `#app`에 CSS `zoom`, 1440×900 이상 권장 | 화면별 기준 뷰포트(기본 1920×1080)로 띄우고 축소 표시 (§4.2) |
| 버전 | `index - old.html`(v1)과 `index.html`(v2)이 같은 `data/`를 씀 | 내용 해시 저장으로 데이터 중복 제거 (§3.3) |
| 외부 의존 | Pretendard CDN (dynamic-subset, woff2 92개 ≈ 3MB) | 동일 폰트의 단일 variable woff2(2.0MB)로 대체해 포함 (§5.3) |
| 기획 문서 | `README.md` 60KB | 화면 개요로 한 번 가져온다 (D-9) |

### 2.1 용량

| 내용 | 문서 내(base64) |
|---|---|
| v2 화면 + data | 1.3MB |
| v1 추가 (data 공유) | +0.12MB |
| Pretendard variable | 2.7MB |
| 런타임 (JS 412KB + CSS 20KB) | 0.43MB |
| **합계 (실측)** | **4.4MB** |

런타임은 CodeMirror(마크다운 편집기) 때문에 128KB → 412KB 로 커졌다. 그중 `@codemirror/view`가 149KB 다. `@codemirror/lang-markdown`은 HTML·CSS·JS 언어 지원을 끌고 와 0.6MB 가 되므로 쓰지 않고, 같은 파서(`@lezer/markdown` + GFM)로 언어를 직접 만든다(`ui/editor/markdownLang.ts`). 녹화 클립은 10초에 1~3MB 가 더해진다.

## 3. 문서 형식

### 3.1 구조

```html
<!doctype html>
<html lang="ko">
<head>
<meta charset="utf-8">
<title>OHT 모니터링 화면정의서</title>
<script type="application/json" id="manna-doc">{ ...문서 데이터... }</script>
<script type="application/octet-stream" id="manna-blob-3f9a…" data-enc="gz64">H4sIA…</script>
<script type="application/octet-stream" id="manna-blob-81c2…" data-enc="b64">d09GMg…</script>
<style id="manna-style">/* 런타임 CSS */</style>
</head>
<body>
<script id="manna-runtime">/* 런타임 JS (IIFE) */</script>
</body>
</html>
```

- **문서 데이터**는 JSON 하나다. 블롭과 분리되어 있으므로 따로 꺼내 읽거나 주고받을 수 있다.
- **블롭**은 화면 파일·외부 리소스·녹화 클립 하나하나다. 이름은 내용의 SHA-256이다. 텍스트는 `gz64`(gzip 후 base64), 이미 압축된 것(woff2, png, webm)은 `b64`로 담는다.
- **저장**은 런타임이 자기 자신을 다시 직렬화하는 것이다. 바뀌는 것은 문서 데이터 JSON 과 새 블롭(클립)뿐이다. 문서가 더는 참조하지 않는 블롭은 저장할 때 빠진다.
- JSON 안의 `<` 와 줄 구분 문자(U+2028·U+2029)는 유니코드 이스케이프로 바꿔 `</script>` 조기 종료를 막는다.

### 3.2 문서 데이터

```ts
interface MannaDoc {
  format: 'manna/1';
  id: string;                  // 문서 UUID. 병합 시 같은 문서인지 판별
  meta: { title; project?; version; createdAt; updatedAt; marker?: MarkerColor };
  changelog: { version; date; author; note }[];
  participants: { name: string; role?: string }[];
  screens: Screen[];
  origin?: { by; at; baseUpdatedAt };   // 수신자가 저장한 회신본이면 기록
}

interface Screen {
  id: string;                  // 'SCR-003'
  title: string;
  notes: string;               // 개요 — 마크다운
  versions: ScreenVersion[];
  annotations: Annotation[];   // 배열 순서가 곧 번호 (§6.1)
}

interface ScreenVersion {
  v: number;
  label?: string;
  entry: string;               // 'index.html' 또는 URL 스냅샷이면 원래 페이지 URL
  source?: { url; mode: 'live' | 'static'; at };   // URL 로 담았을 때
  viewport: { w; h; fit: 'contain' | 'width' };
  files: Record<string, { sha; size; type }>;     // 가상 경로 → 블롭
  external: { url; sha?; type?; excluded?; via?; note?; error? }[];  // 원래 URL → 블롭
}
```

### 3.3 내용 해시와 중복 제거

같은 내용의 파일은 버전이 달라도 블롭 하나다. proto의 v1과 v2는 `data/` 2.9MB를 공유하므로 v1 추가 비용은 HTML 하나뿐이다.

## 4. 화면 구성

### 4.1 레이아웃

Manna와 Bethlehem은 같은 틀을 쓴다. 왼쪽 패널은 없다. Bethlehem 의 작성 기능(작업 폴더·문서 열기, 회신, 화면 추가·새 버전·삭제)은 모두 툴바에 있다.

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ 🌱 [작업폴더명▾][회신 1] 제목⇔ v0.1 │ 보기·피커 │ ↶ ↷ │ ▣ ☾ 이름 · 자동 저장됨 [저장|💾✎] │
├ SCR-001 OHT 모니터링 × │ SCR-002 지도 × │ ▾ ＋ ───────┬─┬─────────────────────┤
├ [v1][v2] 새 버전▾ index.html›detail.html ● 실행 중 │ ⏸ ● ◐ │ − 맞춤 59% + ⤢ 🗑 ┤┃│ ▸ 개요 (접힘)      │
│                                                      │┃│ ─────────────────── │
│              품은 화면 (실제 동작)                    │┃│ Comment 3       ＋  │
│              ① ② ③ 마커                              │┃│ ⠿ ① 이름 · 방금     │
│                                                      │┃│ ⠿ ② … 다른 상태     │
└──────────────────────────────────────────────────────┴─┴─────────────────────┘
                                          끌어서 폭 조절 ┘
```

- **탭**(D-19) — 열어 둔 화면들. 누르면 그 화면(탭마다 마지막으로 보던 버전을 기억), 끌어서 순서, × · 가운데 클릭으로 닫기(마지막 하나는 닫지 않는다). ▾ 는 문서의 모든 화면, ＋ 는 화면 추가(작성자). 열린 탭은 문서마다 이 브라우저에 기억한다.
- **화면 막대** — 버전 칩(누르면 그 버전) · 새 버전 ▾ · 지금 페이지(누르면 첫 페이지로) · 실행 상태(● 실행 중 / 실시간 사이트 / 일시정지 / 멈춤 · 고르는 중 / 녹화 중 / 그림) · 일시정지 · 녹화 · 마커 색 · 배율(D-23) · 전체화면 · 화면 지우기.
- **문서 제목 칸** — 휠(위로 넓게)이나 오른쪽 끝 손잡이로 폭을 바꾼다(120~720px, 더블클릭하면 320px, 이 브라우저에 기억).
- **개요**는 기본으로 접혀 있다.
- **작업폴더명 ▾** 은 폴더 열기(D-20)·문서 열기, dist·returned 폴더 열기, 최근 작업 폴더·최근 문서 10개. **화면 추가 ▾ / 새 버전 ▾** 는 폴더 선택·URL·그림·최근 폴더. 대화상자는 마지막으로 쓴 위치에서 열린다 (`userData/settings.json`).
- **회신 n** 은 작업 폴더의 `returned/` 에 회신본이 들어오면 뜬다. 눌러서 병합한다(§8.3).
- 새 Comment 쓰기, Comment 보기·고치기·답글은 **대상 옆 팝업**이다(오른쪽에 자리가 없으면 왼쪽, 그것도 없으면 아래). 패널의 카드는 순서·목록·미리보기용이다.
- 패널과 스테이지 사이 손잡이를 끌어 패널 폭을 바꾼다(300px ~ 창의 70%, 브라우저에 기억). 더블클릭하면 400px.
- **전체화면**(⤢)은 Fullscreen API 로 창 전체를 쓰고 툴바를 숨긴다. 탭과 화면 막대는 남고, 막대에 피커·패널 단추가 더 붙는다. Esc 로 나간다.
- **단축키** — Ctrl 누른 채 클릭·드래그(피커), Ctrl+Enter(추가), Ctrl+Z / Ctrl+Shift+Z, Ctrl+S / Ctrl+Shift+S, **Delete**(고른 Comment 지우기 — 되돌리기 가능, 남의 것은 작성자만), **Esc**(작성 취소 → Comment 팝업 닫기 → 선택 풀기 → 피커 끄기 → 전체화면 나가기 순), F12(개발자 도구).
- 설명용 각주·안내 문구는 두지 않는다 — 작성 창의 "div.ds 안의 영역" 같은 대상 설명, 이름 묻기·URL·첫 화면의 설명 문단을 뺐다.
- 패널(▣)은 숨길 수 있다.

### 4.2 스테이지

품은 화면은 기준 뷰포트(기본 1920×1080) 크기의 iframe으로 띄우고 `transform: scale()`로 남는 영역에 맞춘다. 화면 자신은 늘 같은 크기에서 돌기 때문에 레이아웃이 작성자가 본 그대로 유지된다.

### 4.3 디자인 토큰

디자인 가이드 §8.1 원시 토큰을 그대로 쓰고, §8.2 시맨틱 매핑으로 라이트/다크를 전환한다(기본 다크, D-18). 면은 세 겹이다 — 스테이지 바탕(`--bg-stage`), 화면 컨테이너(`--bg-container`, 얇은 테두리 · 약한 그림자), 화면 프레임(흰 바탕 · `--frame-border` 1px · 4px 모서리). 떠 있는 것(팝업·대화상자·토스트)만 `--shadow-pop` 을 쓰고, 반투명 막대는 두지 않는다(가이드 §12). 자체 UI는 Pretendard를 쓴다. 문서에 Pretendard 블롭이 있으면 그것을 같이 쓰고, 없으면 시스템 폰트로 폴백한다.

**마커 색.** 마커는 화면 위에 뜨므로 아래 배경이 무엇일지 모른다. 기본(자동)은 마커 자리의 배경 밝기를 0.5초마다 재서(캔버스는 픽셀을, DOM 은 불투명한 배경색을) 어두운 배경이면 흰 바탕·검은 숫자, 밝은 배경이면 그 반대로 고른다. 어느 쪽이든 바깥 고리와 그림자를 둘러 어떤 배경에서도 테두리가 보인다. 툴바의 마커 색(◐)에서 주황·검정·흰색·파랑·노랑·빨강으로 고정할 수 있고, 이 설정은 문서에 저장된다.

**브랜드 자산.** `docs/icon.png`는 창·앱 아이콘과 문서 파비콘(64px)으로, `docs/key_art.png`는 Bethlehem 첫 화면에 쓴다(소개 문구 없이 키 아트와 버튼만). 키 아트는 용량 때문에 문서에 넣지 않는다. 툴바 로고는 키 아트의 잎 마크를 SVG 로 옮긴 것이고, 그 녹색은 로고에만 쓴다.

## 5. 화면 품기

### 5.1 iframe 로딩

1. 엔트리 HTML 블롭을 풀어 `DOMParser`로 읽는다. 원본은 건드리지 않는다.
2. 정적 참조(`script[src]`, `link[href]`, `img[src]`, `srcset`, `source`, `video`, `audio`, 인라인 `style`의 `url()`)를 Blob URL로 바꾼다. CSS 파일은 내부 `url()`을 그 CSS 의 경로 기준으로 풀어 바꾼다. `<base href>` 가 있으면 해석에 반영하고 태그는 지운다.
3. `<head>` 맨 앞에 shim 스크립트를 넣는다.
4. `iframe.srcdoc`으로 띄운다. srcdoc 문서는 부모와 같은 출처이므로 부모가 내부 DOM에 접근할 수 있고, 이것이 Comment 의 전제다.

### 5.2 shim — 실행 중 요청 가로채기

품은 화면의 스크립트보다 먼저 실행되어 `script.src`·`img.src`·`link.href` 세터, `setAttribute`, `fetch`, `XMLHttpRequest.open`, `Worker` 를 패치한다. 받은 경로를 문서 기준으로 풀어 담겨 있으면 Blob URL로 바꾸고, 없으면 그대로 통과시킨다. 풀리지 않은 요청은 스테이지 아래 진단에 원인·위치·조치와 함께 쌓인다.

### 5.3 외부 리소스

Bethlehem(메인 프로세스, CORS 제약 없음)이 등록 시점에 외부 URL을 내려받는다. CSS면 그 안의 `url()`까지 재귀로 받는다. Pretendard dynamic-subset(woff2 92개)은 같은 폰트의 단일 variable woff2로 바꿔 담는다. 리소스별로 체크를 끄면 링크를 그대로 둔다.

### 5.4 일시정지

에이전트(§6.0)가 `requestAnimationFrame`, `performance.now`, `Date.now`, CSS 애니메이션을 감싼다. 일시정지 중에는 rAF 콜백을 보류하고, 재개하면 멈춰 있던 시간만큼 시계를 빼서 넘긴다. 피커를 쓰는 동안(Ctrl 을 누르고 있거나 작성 창이 열려 있는 동안)에는 자동으로 멈춘다 — 편집 화면은 실시간으로 돌고, Comment 를 달 때만 멈춘다.

**멈춤 그림.** Bethlehem 에서는 피커를 켜는 순간 스테이지를 `capturePage` 로 찍어 화면 위에 덮는다. 워커에서 그리는 캔버스처럼 rAF 로 멈출 수 없는 것도 보이는 그대로 멈춘다. 그 아래의 실제 DOM 으로 요소를 고르고, 그 그림은 Comment 의 "달 때 화면"(§6.6)이 된다. 찍은 뒤에 멈추므로 그리던 중인 WebGL 도 그대로 남는다. 브라우저(수신자)에서는 찍을 수 없어 시계만 멈춘다.

### 5.5 URL 화면

주소로 화면을 추가하면 **편집기 안의 webview 에서 실제 사이트가 그대로 돈다.** 로그인도 그 안에서 한다(세션 `persist:terrarium-sites`, 쿠키가 남는다). 폴더 화면과 똑같이 Ctrl 피커·Comment·녹화가 된다.

- webview 의 preload(`preload/site.ts`)가 에이전트를 페이지 스크립트보다 먼저 메인 월드에 넣고(`contextBridge.executeInMainWorld`, 페이지 CSP 에 걸리지 않는다), 에이전트 ↔ 스테이지 메시지를 잇는다. 메인 프로세스가 `will-attach-webview` 에서 preload·sandbox·세션을 강제하고, 다른 세션·스킴은 붙이지 않는다. webview 는 작성 API(`window.bethlehem`)에 닿지 않는다.
- webview 는 `display: inline-flex` 여야 한다 — `block` 이면 안쪽 프레임 높이가 무너져 사이트가 수십 px 높이로 그려진다.
- **보낼 사본.** 사이트가 열리고 4초 뒤, 그리고 Comment 를 단 뒤에 지금 모습을 사본으로 만든다(`main/site.ts`).
  - DOM 을 직렬화한다. 스크립트·`on*` 속성은 빼고, 입력값과 CSSOM(`insertRule`·`adoptedStyleSheets`) 규칙은 글로 옮긴다.
  - **shadow DOM 을 가진 요소와 canvas·video·iframe 은 webview 를 `capturePage` 로 찍어 그 자리만 잘라 배경 그림으로 넣는다.** 요소(태그·id·class)는 그대로 남기므로 Comment 지문이 수신자 문서에서도 맞는다. 테스트 사이트의 지도(`<xms-fe-map-monitor>` 안 WebGL)가 이렇게 담긴다.
  - 직렬화한 HTML 이 가리키는 CSS·글꼴·그림은 사이트 세션(쿠키 포함)으로 내려받는다. CSS 안의 `url()` 까지 따라간다. UTF-8 이 아닌 텍스트는 UTF-8 로 바꾼다.
  - 사본은 그 버전의 `entry`·`external` 로 들어가고, 되돌리기 단계에는 남지 않는다. 사본이 바뀌어도 편집기의 webview 는 다시 불러오지 않는다(버전 열쇠가 사이트 주소 기준).
- **수신자**는 사본을 본다 — 마지막으로 편집기에서 본 모습이다. 지도 같은 부분은 그림이라 움직이지 않지만, 모든 Comment 에는 달 때 화면이 붙어 있다.
- **한계**: 사본은 화면에 보이던 영역(뷰포트)만 픽셀로 담는다. 스크롤 아래의 캔버스는 비어 있을 수 있다.

## 6. Comment — Leaven

### 6.0 에이전트 — 화면 안의 일은 화면 안에서

요소 찾기·위치 계산·피커·클릭 경로·시계 멈추기는 **품은 화면 문서 안에서 도는 에이전트**(`agent/agent.ts`, 단독 IIFE 11KB)가 한다. 스테이지는 메시지로 묻고, 마커·하이라이트·팝업은 스테이지 쪽 DOM 에 그린다. 그래서 폴더 화면(srcdoc iframe, 같은 출처)과 URL 화면(webview, 다른 출처·다른 프로세스)이 같은 코드로 돈다.

| 스테이지 → 에이전트 | 에이전트 → 스테이지 |
|---|---|
| `anchors` (Comment 지문 목록), `picking`, `pause`/`resume` | `ready` (문서가 뜰 때마다 — 스테이지가 상태를 다시 알린다) |
| `hover`/`pick`/`pickRect`/`pickUp`/`pickDown` (요청·응답) | `frame` — 앵커 위치·보임·배경 밝기 (바뀐 프레임에만) |
| `reveal` (빠른 길 / 경로 재생), `setPath` | `key` — Ctrl·Esc·Ctrl+S/Z/Y (화면에 포커스가 있어도 단축키가 듣는다) |

전송: iframe 은 `postMessage`, webview 는 에이전트 → `window.postMessage` → preload → `sendToHost`, 반대로 `webview.send` → preload → `window.postMessage`. 봉투는 `{ __terrHost }` / `{ __terrAgent }`.

### 6.1 데이터

```ts
interface Annotation {          // UI 이름은 Comment
  id: string;
  version: number;              // 붙어 있는 화면 버전
  anchor?: Anchor;              // 없으면 화면 전체에 단 Comment (녹화 클립 등)
  body: string;                 // 마크다운
  clips?: Clip[];               // 녹화한 움직임 (§7)
  author; createdAt; updatedAt;
  replies: { id; author; at; body /* 마크다운 */ }[];
  history: { at; by; field; from; to }[];   // 병합용
}

interface Anchor {
  fp: Fingerprint;
  region?: { x; y; w; h };      // 요소 박스 기준 0~1
  trail: string[];              // 달 때 선택되어 있던 탭·토글 레이블
  path?: { fp: Fingerprint; x; y }[];   // 화면을 연 뒤 달기 전까지의 클릭 (§6.4)
  props?: Record<string, string>;       // 계산된 스타일 (지금은 화면에 보이지 않는다)
}
```

**번호는 따로 저장하지 않는다.** 같은 화면 버전 안에서 배열 순서가 곧 번호다. 패널에서 카드 왼쪽 손잡이(⠿)를 끌어 순서를 바꾸면 마커 번호도 함께 바뀐다. 다른 버전의 항목 자리는 건드리지 않는다.

### 6.2 피커 — 요소 + 영역

- **Ctrl 을 누르고 있는 동안** 피커가 된다(커서 십자, 스테이지에 주황 테두리, "피커" 배지). 떼면 보기로 돌아가고, 잡아 둔 대상의 작성 창은 남는다. 드래그 중에 떼도 영역은 잡힌다. Ctrl+문자 조합(Ctrl+S 등)을 누르면 피커는 바로 꺼진다. 툴바의 "피커"로 고정할 수도 있다.
- **클릭**은 요소를, **드래그**는 그 영역을 품는 가장 깊은 요소(캔버스면 그 캔버스) 안의 상대 영역을 잡는다. `↑`/`↓`(글을 쓰는 중에는 `Alt+↑`/`↓`)로 부모·자식 요소로 옮긴다.
- 화면 전체에 다는 Comment 는 패널의 ＋ 로 만든다.
- 피커를 켜면 화면이 멈춘 그림으로 덮이고(§5.4), 작성 창은 잡은 대상 옆 팝업으로 뜬다.
- Ctrl 뗀 신호를 놓쳐(포커스가 화면과 툴바 사이를 오가는 사이) 피커가 남아 있으면, 마우스가 Ctrl 없이 움직이는 순간 꺼진다.

### 6.3 마크다운 편집기

Comment 본문·답글·개요가 모두 같은 편집기(CodeMirror 6)를 쓴다. 옵시디언식 라이브 미리보기 — 커서가 있는 줄만 마크다운 기호를 보이고, 나머지 줄은 서식만 보인다(제목, 굵게·기울임·취소선, 코드, 인용, 링크, 구분선, 글머리표). `- [ ]` 는 체크박스로 그려지고 누르면 바로 `[x]` 가 된다. Enter 는 목록·체크박스·인용을 이어 쓰고, 빈 항목에서 누르면 목록을 끝낸다. Ctrl+B / Ctrl+I, Ctrl+Enter 로 추가.

남의 Comment·답글은 읽기 전용이지만 체크박스는 누를 수 있다. 작성자(Bethlehem)는 모두 고칠 수 있다.

### 6.4 표시와 화면 상태 찾아가기

마커 레이어는 iframe 바깥에 있다. 매 프레임 앵커 요소의 위치를 스테이지 스케일로 변환해 옮기고, 요소가 보일 때(`checkVisibility()`, 뷰포트 안)만 띄운다. 안 보이는 Comment 는 패널에서 흐리게, "다른 상태" 표시를 붙인다.

**다른 상태의 Comment 를 누르면 그 화면 상태로 간다.** 화면을 연 뒤 사람이 누른 클릭(요소 지문 + 요소 안의 상대 위치)을 적어 두고, Comment 를 달 때 그 경로를 함께 저장한다(`anchor.path`, 최근 24번).

1. **빠른 길** — 경로 중 탭·토글(`role="tab"`, `aria-selected`·`aria-pressed`·`aria-expanded`)이고 지금 선택되지 않은 것만 다시 누른다. 탭 안의 Comment 는 대개 여기서 끝난다.
2. **처음부터** — 그래도 안 보이면 화면을 다시 불러와 경로 전체를 순서대로 누른다. 각 단계는 그 요소가 나타나고, **그 자리를 다른 것(스플래시·로딩 막)이 덮고 있지 않은 상태가 0.25초 이어질 때까지**(최대 15초) 기다린다. 캔버스 위 클릭(FAB 조망 → BAY-4)도 같은 상대 위치에 마우스를 먼저 올리고(호버로 대상을 정하는 화면) pointer·mouse·click 이벤트를 내서 재현한다.
3. **다른 페이지** — Comment 가 다른 HTML 페이지에서 달렸으면(`anchor.page`, D-22) 그 페이지를 열고 2 를 한다. 마커는 지금 페이지의 Comment 만 붙는다. 화면 안의 링크 클릭은 shim 이 가로채 스테이지에 알리고(`manna: 'navigate'`), 스테이지가 그 페이지로 다시 띄운다.

### 6.5 찾기와 재부착

열 때는 `id` → `selector` → 지문 점수 순으로 요소를 찾는다. 새 버전을 등록할 때 "기존 Comment 를 새 버전으로 옮기기"를 고르면 버전 번호만 옮기고, 화면에서는 지문 점수로 다시 찾는다. **신뢰도 표시와 재지정 UI 는 아직 없다** — proto 의 v1 로 옮겼을 때 `#tabB` 에 단 항목이 옛 화면의 다른 탭에 붙는 것을 확인했다(같은 id 가 다른 탭을 가리킨다).

### 6.6 달 때 화면

Comment 를 달 때 찍어 둔 멈춤 그림(§5.4)을 JPEG 블롭으로 Comment 에 붙인다(`shot: { sha, w, h, box }`, box 는 그림 안의 대상 위치 0~1). Comment 를 열면 스테이지에 그 그림과 박스가 먼저 보인다 — 화면이 그 뒤로 재생되어 바뀌었어도 Comment 가 가리키던 모습 그대로다. 아래쪽 "실시간 화면 보기"로 지금 화면으로 돌아간다. 다른 상태에 있는 Comment 라면 그동안 실시간 화면도 그 상태로 이동해 둔다(§6.4). 수신자 브라우저에서 단 Comment 는 그림이 없다(찍을 수 없다).

## 7. 녹화

화면 머리의 ●로 시작·정지한다(최대 60초). 스테이지 영역만 webm(VP9, 2Mbps)으로 담고, 녹화 중에는 마커와 하이라이트를 숨긴다.

- **화면 받기**: `getDisplayMedia`. Bethlehem 은 메인 프로세스가 `setDisplayMediaRequestHandler` 로 요청한 프레임(자기 창)을 바로 건넨다 — 대화상자가 없다. 브라우저는 "이 탭 공유" 대화상자가 뜬다(`preferCurrentTab`). 화면 전체·다른 창을 고르면 거절하고 이 탭을 고르라고 안내한다.
- **자르기**: Region Capture(`cropTo`)가 되면 그것으로, 안 되면 받은 영상을 캔버스에 옮기며 스테이지 자리만 잘라 다시 녹화한다. Bethlehem 실측 1130×636(스테이지와 같은 16:9).
- **붙이기**: 선택한 Comment 가 있으면 그 Comment 에, 없으면 화면 전체 Comment 를 새로 만들어 붙인다. 클립은 `b64` 블롭으로 문서에 들어가고, 카드 안에서 반복 재생된다.

## 8. 저장과 병합

### 8.0 작업 폴더

```
<작업 폴더>/
├── terrarium.json              문서 정보 · 화면 순서 · 참여자 · 변경 이력 · 마지막으로 구운 파일 이름
├── screens/SCR-001/
│   ├── screen.json             제목 · 버전들(파일 → 블롭) · 원본 폴더 연결(link)
│   ├── notes.md                개요
│   └── comments.json           Comment · 답글 · 클립 · 달 때 화면
├── blobs/ab/abcdef…            내용 해시로 저장한 원래 바이트
├── returned/                   돌아온 .terr.html 을 넣는 곳 (병합하면 returned/merged/ 로)
└── dist/<제목>.terr.html        자동으로 구운 최신본 — 이것을 보낸다
```

- 실행하면 **마지막 작업 폴더와 마지막으로 보던 화면·버전이 그대로 열린다.**
- 화면을 폴더에서 등록하면 원본 폴더 경로·시작 파일·포함 파일을 `screen.json` 의 `link` 에 남긴다(보낸 파일에는 들어가지 않는다 — 작성자 컴퓨터의 경로이므로). 원본 폴더를 감시하다가 파일이 바뀌면 "새 버전으로 등록할까요?" 를 띄운다.
- `returned/` 를 감시하다가 같은 문서의 회신본이 들어오면 툴바에 "회신 n" 이 뜬다.
- JSON 은 화면별로 나뉘고 들여쓰기·순서가 고정이다. 바뀐 파일만 다시 쓴다. Git 으로 관리하면 Comment 가 언제 누가 어떻게 바뀌었는지 diff 로 보인다.
- 테라리움 문서 하나를 열면 그 파일에 바로 자동 저장하면서 "작업 폴더로 풀기" 를 권한다. 풀면 위 구조로 펼쳐 이어서 작업한다 — 문서 안의 데이터만으로 작업 폴더를 완전히 복원한다. 풀 폴더는 그 문서가 든 폴더에서 고르기 시작하고, 비어 있지 않아도 된다(이미 작업 폴더인 곳은 거절하고 "그 폴더 열기" 를 권한다).
- **폴더 열기**(D-20) — 고른 폴더를 들여다보고 정한다: `terrarium.json` 이 있으면 그대로 연다 · 테라리움 문서(`.terr.html`)가 있으면 그 문서를 풀어 그 폴더를 작업 폴더로(여럿이면 고른다) · 화면(HTML)이 있으면 그 폴더를 작업 폴더로 하고 화면 등록 창을 연다 · 그 밖(빈 폴더 포함)은 새 작업 폴더. 화면 폴더가 작업 폴더를 겸하면 등록·원본 감시에서 `terrarium.json`·`screens/`·`blobs/`·`dist/`·`returned/`·`*.terr.html` 은 뺀다.
- **그림 화면**(D-21) — 그림을 품은 작은 `index.html` 을 만들어 보통 화면처럼 담는다(기준 뷰포트 = 그림 크기, `source.mode: 'image'`). 창에 여러 장을 끌어다 놓으면 한 장씩 화면이 된다.

### 8.1 저장 — 라이브 문서

고치면 1.2초 뒤 자동으로 저장한다. 툴바에 "자동 저장됨 · 방금" 이 보인다. **저장**(Ctrl+S)은 지금 바로, **다른 이름으로 저장**(Ctrl+Shift+S, 저장 옆 단추)은 사본이다.

| 환경 | 자동 저장 | 저장 | 다른 이름으로 |
|---|---|---|---|
| Bethlehem · 작업 폴더 | 작업 폴더에 쓰고, 3초 더 모아 `dist/` 를 다시 굽는다 | 바로 쓰고 바로 굽는다 | 보낼 파일을 원하는 곳에 |
| Bethlehem · 문서 하나 | 그 `.terr.html` 에 | 같은 파일에 | 새 파일로 저장하고 그 파일을 이어서 편집 |
| 브라우저(수신자) | 이 브라우저의 저장소(IndexedDB)에 초안. 파일을 한 번 지정하면 그 파일에도 | 파일 지정(Chrome·Edge) 또는 다운로드 | 다시 지정 |

- 브라우저는 열린 파일에 마음대로 쓸 수 없다. 그래서 초안은 늘 브라우저에 남고, 같은 문서를 다시 열면 더 새 초안을 **이어서 연다**. 상태 표시의 "파일에도 자동 저장" 을 한 번 누르면(파일 지정) 그 뒤로는 파일에도 자동으로 쓴다. 그 핸들도 기억해 다음에는 허용만 누르면 된다.
- 확장자를 빼거나 `.html` 로만 적어도 `.terr.html` 로 맞춘다. 수신자가 저장하면 받은 파일 이름 뒤에 자기 이름이 붙는다 (`proto.terr.html` → `proto_홍길동.terr.html`).
- 창을 닫을 때 남은 자동 저장이 있으면 마저 쓰고 닫는다.

### 8.2 되돌리기

문서를 고치는 모든 동작(Comment·답글·개요·순서·마커 색·화면 등록·삭제)은 고치기 직전 문서 JSON 을 쌓는다(최대 100단계). 같은 Comment 를 이어 타이핑하면 2초 안의 변경은 한 단계로 묶는다. **Ctrl+Z / Ctrl+Shift+Z(Ctrl+Y)**, 툴바 ↶ ↷. 글을 쓰는 중에는 편집기 자체의 되돌리기가 먼저다. 블롭은 덧붙기만 하므로 되돌리지 않고, 저장할 때 참조되지 않는 것은 빠진다.

### 8.3 병합

`returned/` 의 회신본을 "회신 n" 에서 병합한다(`core/src/merge.ts`). 같은 `doc.id` 만 합친다.

- Comment·답글은 id 로 맞춰, 원본에 없는 것은 덧붙인다(순서는 원본 다음).
- 같은 Comment 의 본문이 다르면: 회신본을 보낼 때(`origin.baseUpdatedAt`) 이후 원본이 그대로면 회신본을 쓰고, 원본도 바뀌었으면 **충돌** — 원본은 두고 회신본 본문을 답글로 남긴다. 아무것도 잃지 않는다.
- 개요도 같은 규칙. 클립·달 때 화면·참여자는 합집합. 변경 이력에 병합 기록을 남긴다. 되돌리기로 병합 전으로 돌아갈 수 있다.
- 병합한 파일은 `returned/merged/` 로 옮긴다.

```
Bethlehem/
├── package.json             패키지 하나 · npm start = 빌드 → run/ 실행본 → 실행
├── electron.vite.config.ts  main · preload(index, site · cjs) · renderer
├── apps/bethlehem/
│   ├── main/                index(창·IPC·최근 경로·감시) · workspace(작업 폴더 읽기·쓰기·dist·returned) · site(URL 화면 사본)

│   ├── shared/              preload ↔ renderer API 타입
│   ├── renderer/            세션(작업 폴더·문서·자동 저장·병합), 툴바 도구, 화면 등록·URL 대화상자, 첫 화면
│   └── resources/           앱 아이콘
├── packages/
│   ├── core/src/            문서 스키마, 블롭 코덱, 가상 FS, Leaven(지문·찾기), 문서 읽기·쓰기, 병합 — 브라우저/Node 공용
│   ├── core/node/           폴더 훑기·패키징, 문자 인코딩 변환 — Node 전용
│   └── manna/src/
│       ├── agent/           에이전트 — 품은 화면 안에서 (시계·앵커·피커·경로) · 메시지 규약
│       ├── stage/           스테이지(iframe·webview·마커·멈춤 그림·달 때 화면) · 다리 · shim · 로더 · 녹화
│       └── ui/ …            틀(App), 팝업, 패널, 툴바, 마크다운 편집기, 상태·되돌리기·자동 저장(host)
├── scripts/bake.ts          명령줄 굽기
├── tests/                   e2e.ts(문서, Chrome) · e2e-bethlehem.ts(Electron)
├── example/proto/           첫 빵
└── docs/
```

**보안.** Electron 렌더러는 `contextIsolation`, `sandbox` 로 띄운다. 폴더 화면은 작성 UI 와 같은 출처(srcdoc)에서 돌기 때문에 `window.parent.bethlehem` 을 부를 수 있다. 그래서 메인 프로세스는 사용자가 대화상자로 고르거나 끌어다 놓은 경로, 예전에 그렇게 고른 최근 목록과 작업 폴더만 읽고 쓴다. URL 화면은 별도 세션의 webview 에서 sandbox 로 돌고, 메인 프로세스가 preload 를 강제하며, 작성 API 에 닿지 않는다.

**구현 메모.** 문서는 제자리에서 고치므로 `@preact/signals` 의 얕은 props 비교에 걸려 다시 그려지지 않는 컴포넌트가 생긴다. 문서 내용을 그리는 컴포넌트(툴바, 개요, 카드, 상세, 마커)는 `rev` 를 읽어 구독한다.

**알려진 문제**
- 편집기를 맨 위로 스크롤시키는 순간(Ctrl+Home)에 글자를 한꺼번에 쏟아 넣으면 순서가 섞인다(CodeMirror 의 안쪽 스크롤 + 아주 빠른 자동 입력에서만, 사람 속도에서는 재현되지 않음). 테스트는 사람 속도로 친다.
- 첫 Ctrl 피커가 드물게 잡히지 않는다(앱 E2E 4번 중 1번, 작업 폴더를 막 만든 직후). 원인을 찾지 못해 테스트는 한 번 더 시도하고 기록한다.
- URL 화면에서 Ctrl 뗀 신호를 놓쳐 "피커" 배지가 남는 경우를 테스트에서 한 번 봤다. 마우스가 Ctrl 없이 움직이면 꺼지도록 했다.
- 사본은 뷰포트 안의 캔버스만 픽셀로 담는다.

자동으로 확인하지 못한 것: 브라우저의 실제 "이 탭 공유" 대화상자(테스트는 가짜 스트림), `showSaveFilePicker` 덮어쓰기와 "파일에도 자동 저장" 권한 흐름(대화상자), 로그인이 필요한 사이트.
